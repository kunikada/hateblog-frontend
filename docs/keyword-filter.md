# キーワードフィルタ仕様

## 位置づけ

- 機能一覧: [features.md](./features.md) の「フィルタ／検索」。
- 本書は追加予定の仕様を定義する。
- 本書の作成時点では機能の実装は行わない。

## 目的

- 閲覧中の記事一覧をキーワードで絞り込めるようにする。
- 通常のキーワードは、その語を含む記事の表示条件とする。
- 先頭に `-` を付けたキーワードは、その語を含む記事の除外条件とする。

## 対象画面

- トップページに表示するエントリー一覧。
- 日付別の新着順・人気順エントリー一覧。
- タグ別一覧と検索結果一覧。

## 対象外

- アーカイブの日付別件数やカレンダーは対象外とする。
- ランキングと閲覧履歴への適用は初期対応に含めない。
- サイドバーのタグやリンクは絞り込まない。

## 検索との関係

- 検索フォームは検索 API によるサイト内検索を担当する。
- キーワードフィルタは、現在の一覧で取得した記事を対象にする。
- フィルタの適用で検索ページへ遷移しない。

## 対象フィールド

- 記事タイトル、抜粋、記事 URL を対象とする。
- タグ名は抜粋から生成されるため対象としない。
- いずれかのフィールドに語が含まれれば、その語に一致したと判定する。
- リンク先の記事本文を追加取得して判定する処理は行わない。

## 欠損値の扱い

- 抜粋がない場合は空文字列として扱う。
- 異なるフィールドの末尾と先頭を連結した一致は認めない。

## 入力 UI

- はてブ件数フィルタと同じ領域に入力欄を設置する。
- プレースホルダーは「キーワード」とする。
- 入力欄内にクリア用のアイコンボタンを置く。
- 入力値があるときにクリアアイコンを表示する。

## 絞り込みの反映

- 入力の変更を即座に入力欄に表示する。
- 最後の入力変更から 500 ms 経過した時点で、自動で絞り込む。
- 待機中に入力が変わったら、前回の処理予約を取り消して待ち時間を計り直す。
- 待機中は直前の絞り込み結果を表示する。
- 入力欄からフォーカスが外れたら（blur）、待機中の処理を取り消し、最新の確定済み入力値を即時に反映する。

## クリア操作

- クリアアイコンの操作で入力欄を空にし、絞り込みを即座に解除する。
- 待機中の処理を取り消し、保存値も空にする。

## 日本語入力

- IME の変換開始時に、待機中の処理を取り消す。
- 変換中の文字列は入力欄に表示する。
- 変換確定後の入力値を保存し、確定から 500 ms 後に絞り込む。
- フォーカスが外れる操作で変換も確定した場合は、確定した入力値を即時に反映する。

## 語の分割

- 入力全体の前後の空白を除去する。
- 半角・全角スペース、タブ、改行を含む連続した空白で分割する。
- 空の語は条件に含めない。

## 通常の語

- 先頭が半角の `-` でない語を表示条件とする。
- 各語について対象フィールドへの部分一致で判定する。
- 空白を含むフレーズを一つの語として扱う構文は設けない。

## 除外する語

- 先頭が半角の `-` の語を除外条件とする。
- 先頭の `-` を一つ取り除いた残りの文字列を照合する。
- 語の途中にある `-` は文字列の一部として扱う。

## 特殊構文

- 正規表現やワイルドカードは解釈しない。
- 引用符、括弧、演算子名に特別な意味を持たせない。
- 先頭の `-` を通常文字として検索するエスケープ構文は設けない。

## 正規化

- 条件の語と対象フィールドの両方に Unicode NFKC 正規化を適用する。
- 正規化した文字列を小文字化して照合する。
- ひらがな・カタカナの相互変換や読みの補完は行わない。

## 記号の扱い

- 除外指定の判定は、語を正規化する前に行う。
- 全角のマイナスや長音符を除外指定として解釈しない。
- URL のデコード、区切り記号の除去、単語境界の推測は行わない。

## 複数条件

- 通常の語は、指定されたすべての語への一致を必要とする。
- 除外する語は、一つでも一致した記事を非表示にする。
- 通常の語ごとに、一致するフィールドが異なっていてもよい。

## 条件の組み合わせ

- 除外する語だけの指定も許可する。
- 通常の語と除外する語に同じ語があれば、該当記事は表示しない。
- 正規化後に重複する同種の条件は一つとして扱う。

## 空入力と入力途中の記号

- 空文字列または空白のみの入力でフィルタを解除する。
- `-` 単独の語は除外語の入力途中として条件から省く。
- 有効な語が残る場合は、残った語で絞り込む。
- 有効な語がない場合は、キーワード条件なしとして表示する。

## はてブ件数との併用

- はてブ件数条件とキーワード条件を両方満たす記事を表示する。
- キーワードを適用しても選択中のはてブ件数条件は変更しない。
- キーワードのクリアで、はてブ件数条件を解除しない。

## 並び順と表示範囲

- 絞り込みによって記事の並び順を変更しない。
- 表示件数で切り出す前の取得済み記事全体に条件を適用する。
- 条件の適用・解除時は、絞り込み後の先頭から表示する。
- トップ・日付別一覧の既存の件数表示には絞り込み後の件数を使う。

## 追加読み込み

- 追加取得した記事にも現在の適用済み条件を適用する。
- 一致記事がないページでも、取得元に続きがあれば追加取得を可能にする。
- 未取得の記事を探すための無制限な自動取得は行わない。

## 未取得データがある場合

- 一致記事がない場合にも「さらに読み込む」操作を表示する。
- 取得中は操作を無効化し、完了後に再度操作できるようにする。
- API の offset は絞り込み後の件数ではなく、取得元の進行に従う。

## 該当なしの表示

- 続きがある場合は、取得済み記事内に一致がない旨を表示する。
- 全件取得済みの場合は、条件に一致する記事がない旨を表示する。
- 入力欄とクリア操作は、該当なしの場合も利用できるようにする。

## 状態の保持

- 入力値と、一覧に反映した条件を分けて管理する。
- 対象画面すべてで一つの入力値を共有する。
- 日付・タグ・検索語・並び順・はてブ件数の変更や画面遷移をまたいで入力値を保持する。
- 再読み込みやブラウザーの再起動後も、保存した入力値を復元して絞り込みに使う。

## 保存先

- 現在のサイトの `localStorage` に `keywordFilter:v1` をキーとして保存する。
- はてブ件数フィルタの `minUsers:v1` と同様に、既存の `useLocalStorage` を使う。
- 入力欄の文字列を正規化前の形で保存し、復元時に同じ内容を表示する。
- 通常の入力変更は絞り込みの待機時間とは別に保存する。
- 保存は同じブラウザープロファイルとオリジンの範囲で有効とする。
- 保存値がない場合やサイトデータを削除した場合は、空欄から始める。
- `localStorage` が利用できない場合は、その画面で入力と絞り込みを利用できる。

## 通信

- キーワード条件の適用だけでは API の再取得を行わない。
- 既存の API パラメータや OpenAPI 定義は変更しない。
- キーワードはブラウザー内で扱う。

## 追加取得のエラー

- 追加取得に失敗しても、取得済み記事への適用済み条件を維持する。
- 再取得操作で条件を初期化しない。

## 入力欄とボタンの属性

- 入力欄に `aria-label="キーワード"` を設定する。
- クリアアイコンには標準のボタンを使い、`aria-label="キーワードをクリア"` を設定する。
- スマートフォンでは操作群を折り返し、横方向にはみ出さないようにする。

## 判定処理

- 語の分割と正規化は適用時に行う。
- 一覧の再描画ごとに入力文字列を再解析しない。
- 記事データと API キャッシュの元データは書き換えない。
- 入力文字列は通常のテキストとして表示する。

## 受け入れ条件

- 通常語による絞り込みと `-` による除外を併用できる。
- 複数語、正規化、欠損値、空入力、単独の `-` が本書どおりに扱われる。
- 最後の入力変更または IME の変換確定から 500 ms 後に絞り込まれる。
- 待機中にフォーカスが外れた場合は最新の確定済み入力値で即時に絞り込まれ、予約していた処理は実行されない。
- ページ遷移や再読み込み後に入力値が復元され、クリア後は空欄になる。
- はてブ件数との併用、クリア、追加取得が本書どおりに動作する。
